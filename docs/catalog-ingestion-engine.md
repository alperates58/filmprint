# TMDB Catalog Ingestion Engine

**Background Film & TV Database Population Infrastructure**

---

## 1. Overview & Architecture

The TMDB Catalog Ingestion Engine is an enterprise-grade, background-driven catalog population subsystem built into Filmprint. It is engineered to scale the Movie and TV Show catalog from the initial bootstrap baseline (~2K Movies, ~500 TV Shows) to mature production targets (**100,000 Usable Movies** and **30,000 Usable TV Shows**) without ever blocking or slowing down live user interactions.

## 2. Key Architecture Components

### 2.1 Decoupled Ingestion & Database-First Serving
- User flows (Calibration Engine, Discovery Home, Universal Matcher, Group Matcher) **never make synchronous TMDB network calls**.
- All user requests are served directly from the local PostgreSQL database.
- When a user rates films or requests recommendations, candidate selection operates exclusively against the persisted, indexed database.

### 2.2 Global Master Switch & Persistence
- Single Source of Truth: `SystemSetting` table key `catalog_ingestion_master_enabled` (`true` / `false`).
- Admin UI, Admin API routes, CLI scripts, and the background worker all read this identical configuration.
- Turning the Master Switch **OFF** halts all outgoing TMDB ingestion requests immediately.

### 2.3 TMDB Daily ID Export & Streaming Discovery
- Uses official TMDB Daily ID Exports (`http://files.tmdb.org/p/exports/movie_ids_MM_DD_YYYY.json.gz` and `tv_series_ids_MM_DD_YYYY.json.gz`).
- Implements streaming decompressive reading via `zlib.createGunzip()` and `readline`. The entire file (~50-100MB uncompressed) is never loaded into memory at once.
- Supports date fallback: if today's file is not yet generated by TMDB (typically before 08:00 UTC), yesterday's or 2 days ago export is used.
- If TMDB file servers are completely unreachable, `DiscoverApiFallbackProvider` smoothly takes over.

### 2.4 Token-Bucket Rate Limiter & TMDB 429 Handling
- **Shared Global Limiter**: Enforces a strict global maximum RPS (`catalog_ingestion_global_max_rps`, default 4.0 req/s) across all workers.
- **Per-Worker Limiter**: Individual media workers (Film, TV) can be tuned separately (e.g. 1.0 req/s each).
- **429 Handling**: Automatically parses `Retry-After` headers (both integer seconds and RFC HTTP dates). Pauses token refill and enforces exponential backoff with jitter.

### 2.5 Circuit Breaker
- Tracks consecutive network/5xx failures.
- Threshold: 10 consecutive failures.
- When tripped to `OPEN`, ingestion is suspended for 5 minutes (`circuitCooldownMs = 300_000`), protecting TMDB and the application.
- Supports manual reset via Admin UI or CLI.

### 2.6 Distributed Worker Lock
- Stored on `CatalogIngestionState` (`lockedAt`, `lockedBy`).
- Lease TTL: 60 seconds. Heartbeat: 15 seconds.
- Automatically recovers from orphaned locks if a container crashes or is abruptly killed.

### 2.7 Candidate State & Rejection Memory
- `CatalogCandidateState` stores every evaluated candidate with `[mediaType, tmdbId]`.
- Permanent terminal statuses (`IMPORTED`, `REJECTED`, `NOT_FOUND`, `ADULT`, `UNSAFE`, `NO_USABLE_TITLE`, `NO_OVERVIEW`) are never re-fetched.
- Transient errors (`FAILED_RETRYABLE`) are retried after an exponential backoff period (`retryAfter`).

## 3. Safety, Quality & Usable Catalog Policy

To ensure the 100K Movie and 30K TV Show targets represent **usable, high-quality catalog items**, every candidate passes through strict quality gating:

1. **Adult & Explicit Content Filtering**:
   - `adult === true` candidates in the export feed are rejected immediately without detail requests.
   - Text analysis screens against pornography/hardcore keywords in titles and descriptions.
2. **Title Script & Safety Rules**:
   - Numeric titles (`1917`, `2012`, `11.22.63`, `24`, `300`, `9`, `1408`) are fully supported and valid.
   - Pure non-Latin titles (CJK, Cyrillic, Arabic) without a Turkish or English Latin fallback are rejected with `REJECTED_NO_USABLE_TITLE`.
3. **Overview & Synopsis Integrity**:
   - Placeholder synopsis phrases (`Film hakkında özet bilgi bulunmuyor.`, `Dizi hakkında özet bilgi bulunmuyor.`, `No overview available`) are identified and never stored as valid descriptions.
   - Candidates missing meaningful synopses in both Turkish and English are evaluated according to mode safety thresholds.
4. **Field-by-Field Localization Merger**:
   - Preserves Turkish display titles when available while falling back to high-quality English synopsis when Turkish synopsis is absent or empty.

## 4. Production Worker Packaging & Docker Deployment

### 4.1 Standalone Production Architecture
In production Next.js Docker environments (Next.js Standalone), `devDependencies` such as `tsx` are omitted in the runtime container (`--omit=dev`).

To guarantee 100% reliability without dependency errors:
1. `scripts/build-worker.mjs` uses the TypeScript compiler API to bundle `scripts/catalog-worker.ts`, `scripts/catalog-ingest.ts`, and `scripts/catalog-status.ts` into pure CommonJS modules in `dist/`.
2. The `Dockerfile` builder stage compiles the worker bundle during `npm run build`, and the runner stage copies `/app/dist` to the production image.
3. The `catalog-worker` service in `docker-compose.yml` runs natively via `node dist/catalog-worker.js`.

## 5. CLI Reference

### 5.1 Manual Ingestion & Dry-Run Evaluation
```bash
# Dry-run 50 movies (evaluates candidates with zero database writes)
npm run catalog:ingest -- --media=movie --dry-run --limit=50

# Live apply 100 movies in batches of 25
npm run catalog:ingest -- --media=movie --apply --limit=100 --batch-size=25

# Dry-run 50 TV shows
npm run catalog:ingest -- --media=tv --dry-run --limit=50
```

### 5.2 Status Inspection
```bash
# View master status, counts, progress %, and circuit breaker states
npm run catalog:status
```

### 5.3 Background Worker
```bash
# Development (with tsx)
npm run catalog:worker

# Production (with compiled JS)
npm run catalog:worker:prod
```

  - Fields: `masterEnabled`, `globalMaxRps`, `staleDays`, `film`, `tv`
